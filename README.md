# dbt in Practice — Sutton Tennis Club

The companion repo for *dbt in Practice*, a Pearson LiveLessons course. This
is one dbt v2 project, for a fictional club called Sutton Tennis Club,
that grows one lesson at a time. Every lesson has a starting point, a
finished state, and a doc explaining the theory and the how-to — all three
live in this one repo, found through git tags.

Nothing here is real: no real club, no real member, no real reservation.
The data is synthetic, generated by a script you can read.

## How this repo is organized

- **One project, growing lesson by lesson.** There's no `lesson-3/`,
  `lesson-4/` folder, and no separate branch per lesson — every lesson
  builds on the dbt project the previous one left behind, so it's one
  project with a linear history.
- **Git tags mark where each lesson starts and ends.** `lesson-3-start` and
  `lesson-2-end` point at the exact same commit — whichever name makes
  sense for what you're trying to do, checkout either one.
- **`docs/` holds the theory and the how-to**, one file per lesson, written
  as you reach that lesson. By the last tag, `docs/` is the complete course
  reference — not just a pile of code.

| Lesson | Tag (end of lesson / start of next) | Doc |
|---|---|---|
| Introduction | `lesson-1-start` | [docs/00-introduction.md](docs/00-introduction.md) |
| 1. Setup | `lesson-1-end` | [docs/01-setup.md](docs/01-setup.md) |
| 2. AI Infrastructure | `lesson-2-end` | docs/02-ai-infrastructure.md |
| 3. Sources | `lesson-3-end` | docs/03-sources.md |
| 4. Development | `lesson-4-end` | docs/04-development.md |
| 5. Documentation | `lesson-5-end` | docs/05-documentation.md |
| 6. Testing | `lesson-6-end` | docs/06-testing.md |
| 7. Governance | `lesson-7-end` | docs/07-governance.md |
| 8. Deployment | `lesson-8-end` (= `main`) | docs/08-deployment.md |

To start lesson *N* exactly where the lesson leaves off in the video:

```bash
git checkout lesson-4-start
```

`main` always points at the most recently finished lesson — right now,
that's wherever this build has gotten to.

## Setup

Two things to install, nothing to sign up for:

1. **[dbt v2](https://docs.getdbt.com/docs/fusion/about-fusion)** (the
   Fusion engine). This project requires it — see
   [docs/01-setup.md](docs/01-setup.md) for why.
2. **[DuckDB](https://duckdb.org/docs/installation/)** (the CLI). Used once,
   outside of dbt, to load the raw data — dbt itself never touches
   `data/raw/`.

Then, from the repo root:

```bash
python3 scripts/load_raw_data.py      # loads data/raw/*.csv into sutton.duckdb's raw schema
dbt deps                              # once a lesson introduces a package
dbt build --profiles-dir .
```

Every `dbt` command in this repo's docs assumes `--profiles-dir .` (or
`export DBT_PROFILES_DIR=.` once, for the session) — `profiles.yml` lives in
the repo, not in `~/.dbt/`, so there's nothing outside the clone to manage.
If dbt ever resolves to the wrong project (a stray `DBT_PROJECT_DIR` in
your shell profile from another project is the usual cause), add
`--project-dir .` as well.

### Regenerating the data

`data/raw/*.csv` is already committed, so the step above is all you need.
To generate a fresh (still internally consistent) dataset of your own:

```bash
python3 scripts/generate_demo_data.py --seed 7 --members 300
python3 scripts/load_raw_data.py
```

See the docstring at the top of
[scripts/generate_demo_data.py](scripts/generate_demo_data.py) for what's
deliberately messy in this data, and why — several quirks exist specifically
to motivate a lesson's live demo, not by accident.
